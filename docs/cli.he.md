# מדריך הפקודות — `tools/vf.py`

מריצים משורש המאגר: `python3 tools/vf.py <command> …`. `<project>` הוא שם תחת
`projects/` (או נתיב). ספרייה סטנדרטית בלבד.

הפלט שקט: שורה אחת לכל שלב. ‏`VF_VERBOSE=1` מציג כל פקודת ffmpeg או ffmpeg-skill שרצה מתחת. לפני רינדור או ייצוא, ‏`story.json` נבדק כולו, וכל הבעיות (מקור או תבנית שלא קיימים, מוזיקה, LUT או תרגום חסרים, חלק קצר מדי למעברים שלו, מזהים כפולים) מוצגות בבת אחת, לפני שמשהו מתרנדר.

## doctor
בודק את ffmpeg-full ואת המסננים שלו (subtitles, ass, drawtext, xfade, tile), את ffmpeg-skill,
את whisper-cli ואת המודל, ואת Node.js לגרפיקה המונפשת. מחזיר קוד יציאה 1 אם חסר משהו
הכרחי.

## new `<name> [video|folder]… [--copy] [--language L]`
יוצר את `projects/<name>/` (source, transcript, visual, parts, renders) ו**מקשר** את קובצי המקור.
תיקייה מוסיפה את קובצי הווידאו שברמה העליונה שלה (`.mp4 .mov .m4v .mkv .webm .avi .mts`). בטוח
להריץ שוב, ואפשר גם להוסיף קובץ לפרויקט קיים. `--copy` מעתיק במקום לקשר (כונן חיצוני, תיקיית
ענן, מקורות שעומדים לזוז). קובצי ענן שלא הורדו (placeholders) נדחים. הקלטים נבדקים לפני
שנוצר משהו.

בלי קובץ וידאו נוצר פרויקט ריק (לסרטון מונחה תסריט או לגרפיקה בלבד). אפשר להוסיף חומר מאוחר יותר באותה דרך.
‏`--language en|he|es…` שומר את שפת הפרויקט ב-`project.json`. בלעדיו, התמלול הראשון מזהה אותה.

## transcribe `<project>` [options]
תמלול אחד לכל קובץ מקור, `transcript/<src>.json` (מקטעים עם מילים, בשניות) ועוד `.srt`.

| דגל | ברירת מחדל | |
|---|---|---|
| `--language` | של הפרויקט; אחרת זיהוי | שפת הדיבור; זיהוי דורש את המודל הרב-לשוני |
| `--prompt` | — | שמות ומונחים, כמשפט קצר |
| `--model` | ‏ivrit.ai לעברית, רב-לשוני לשאר | קובץ מודל ggml |
| `--force` | כבוי | תמלול מחדש של תמלולים קיימים |

## transcript `<project> [--words]`
מדפיס את המקטעים של כל קובץ מקור בצורה `[src#N mm:ss.ss-mm:ss.ss] text`, משולבים עם שורות
`VISUAL` מתוך `visual/<src>.json` ושורות `WATCH` מתוך `visual/<src>.watch.json` של מודל ראייה. `--words` מוסיף כל מילה עם הזמן שלה; `*` מסמן הברת היסוס.

## frames `<project> [--every N] [--width W] [--threshold T]`
גיליונות תמונות ממוזערות של 12 אריחים עם קוד זמן (`visual/<src>_sheet_NNN.png`, אריח אחד כל N
שניות, ברירת מחדל כ-48 אריחים לכל קובץ מקור) ורשימת סצנות (`visual/<src>.scenes.json`).

## watch `<project> [--task log|clips|qa] [--provider P] [--base-url URL] [--model M] [--allow-cloud]`
מודל ראייה שאתם בוחרים מסתכל על החומר ו**מציע**, ואף פעם לא חותך. ‏`log` (ברירת מחדל) כותב
‏`visual/<src>.watch.json` (שוטים, איכות, אנרגיה, הצעות לצילומי אווירה ולשוט מרכזי), ו-`transcript`
מציג אותם כשורות `WATCH`. ‏`clips` מוסיף `visual` ו-`combined` לכל מועמד ב-`candidates.json`. ‏`qa`
כותב `renders/<name>.watch.json` עם בעיות אפשריות ברינדור (`--render final|draft|reels…`).
‏`--every N` שניות בין פריימים, `--batch N` פריימים לבקשה, `--only` קובצי מקור ל-`log`. איפה יושב
ה-API (בדגלים, או `VF_VISION_*` ב-`.env`), שרתים מקומיים ובענן ופרטיות: [מודל ראייה](vision.he.md).

## status `[project]`

איפה כל פרויקט עומד: קובצי המקור (ולכל אחד, האם יש לו תמלול, הערות ויזואליות או קישור שבור), תדריך, תסריט, מיתוג וקריינות, מספר החלקים והגרסאות בסיפור, הרינדורים עם אורך ושעה, ו**הצעד הבא**. בלי שם פרויקט, היא מציגה את כולם.

## reference `<project> <video> [--every N] [--threshold T]`

לומד סרטון שרוצים לחקות (פרסומת, תדמית של מתחרה, סגנון שאוהבים). כותב את `reference/<name>/shots.json` (כל צילום ואורכו, אורך צילום חציוני וחיתוכים לדקה), גיליונות של כל הסרטון ו-`transitions.png`: שלושה פריימים סביב כל אחד מהחיתוכים הראשונים, כדי להבחין בין חיתוך חד, התמזגות, ניגוב או הבזק. ‏Claude קורא אותם, כותב את `reference/<name>/style.md`, ומעביר את הקצב, המעברים, סגנון הכתוביות והגרפיקה אל `story.json`. לקישור יש להוריד קודם, עם התוסף `/watch` או עם `yt-dlp`.

## scenes `<project> [--threshold T]`
מדפיס את חילופי הסצנות בכל קובץ מקור.

## render `<project>` [options]
מרנדר את `story.json` (ראו [מדריך story.json](story-json.he.md)) אל `renders/final.mp4`.

| דגל | |
|---|---|
| `--draft` | איכות תצוגה מקדימה מהירה ← `renders/draft.mp4`; מדלג על נרמול העוצמה |
| `--version V` | גרסה מתוך `story.json` ← `renders/V.mp4` |
| `--force` | חיתוך מחדש של כל חלקי החומר המצולם |
| `--keep-stages` | שומר את `renders/.stages-<name>/` (קובץ הביניים של כל שלב) |

הפקודה מדפיסה את האורך האמיתי של כל חלק, מה הניקוי הסיר, ואת משך הזמן המתוכנן מול המשך
בפועל. היא גם כותבת `captions.srt`, `captions.words.json`, `captions.<lang>.srt` וגיליון
תמונות ממוזערות `renders/<name>_sheet.png`.

טיוטה של גרסה נשמרת ב-`renders/<version>_draft.mp4`, כך שהיא לעולם לא מחליפה את הגרסה עצמה. בסוף כל רינדור רצה **בדיקת איכות**: האורך תואם לתכנון, הגודל, ערוצי הווידאו והשמע, הכתוביות וערוצי הכתוביות. אם משהו לא תקין, היא אומרת מה, ויוצאת עם קוד 2, כך שקובץ פגום לא מדווח כמוכן.

## voice `<project>` [options]
קריינות מתוך `script.md`; ראו [קריינות](voiceover.he.md).

| דגל | ברירת מחדל | |
|---|---|---|
| `--provider` | `say` ב-macOS, חובה במערכות אחרות | `elevenlabs`, `azure`, `google`, `openai`, `say` |
| `--voice` | ברירת המחדל של הספק | מזהה / שם של קול |
| `--model` | ברירת המחדל של הספק | למשל `eleven_v3`, `gpt-4o-mini-tts` |
| `--script` | `script.md` | |
| `--language` | של הפרויקט | |
| `--speed` | `1.0` | |
| `--gap` | `0.6` | שניות שקט בין מקטעים |
| `--only` | — | הקראה מחדש רק של המקטעים האלה, למשל `2,5` |

## beats `<project> <music file>`
קצב, מספר הפעמות ותחילתה של כל תיבה, כדי שאפשר יהיה לחתוך חלקים לפי המוזיקה. הרשת המלאה
נכתבת אל `renders/<music>.beats.json`.

## review `<project> [--version V] [--draft] [--lang en|he]`
כותב את `renders/<render>_review.html` לצד הסרטון: דף סטטי אחד, בלי שרת. בדף יש את הסרטון, **ציר זמן ויזואלי** (חלקים ומעברים, שכבות, צילומי אווירה, כתוביות ושמע, עם סמן מיקום), והערות לפי זמן. בציר אפשר לגרור חלקים לסדר חדש ולשנות כל מעבר. הכול יוצא כבקשה אחת בטקסט לעורך. ‏`--lang` קובע את שפת הפתיחה (ברירת מחדל: עברית בפרויקט בעברית, אחרת אנגלית), ובדף יש מתג עברית/אנגלית. ראו [מסירה](delivery.he.md).

## candidates `<project> [--min 15] [--max 60] [--top 12]`
מוצא רגעים שיכולים לעמוד לבד כסרטון קצר. הוא בוחן חלונות של מקטעי תמלול שלמים ומדרג אותם לפי וו (hook) במשפט הראשון (שאלה, מספר, מילים חזקות), מספרים, קצב, הברות היסוס וסיום שלם. הוא מדפיס רשימה מדורגת וכותב את `candidates.json` עם הטקסט המלא של כל רגע. הציון רק מכוון: Claude קורא את הטקסט ומחליט.

## clips `<project> [--only c1,c3] [--draft]`
מרנדר את `clips.json` (ראו [מסירה](delivery.he.md)) כסרטונים קצרים: `renders/clip_<id>.mp4`, אנכיים כברירת מחדל ומנוקים, עם כתוביות מילה-אחר-מילה, כותרת וו בשניות הראשונות, לוגו, ושקופית סיום לבחירה. כל קליפ עובר את בדיקת האיכות.

## export `<project> [--format fcpxml|edl|otio] [--version V]`
העריכה כציר זמן לתוכנת עריכה ב-`renders/edit.<format>`, שמצביע על הקבצים המקוריים. כרטיסי
הגרפיקה מרונדרים ונכללים כקליפים.

## ff `<tool> [args…]`
מריץ כל כלי של ffmpeg-skill כש-ffmpeg-full נמצא ב-PATH, למשל `vf.py ff check renders/final.mp4
--platform reels`. `vf.py ff <tool> --help` מציג את הדגלים שלו; טבלת הבקשות
נמצאת ב-`.claude/skills/ffmpeg-skill/SKILL.md`.
